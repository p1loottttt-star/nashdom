# «Наш дом» → платформа для пар: дизайн

06.10.2026. Ваня просил работать самостоятельно, поэтому решения на развилках приняты здесь, без опроса. Каждое помечено, его можно пересмотреть.

## Что строим
Любая пара заводит свой 3D-дом. Двое входят под своими аккаунтами и видят одно и то же: записки, фото, альбомы, планы, мысли. Изменения приходят партнёру сразу. В ноутбуке появляются новые приложения:
- **CoupleTube**: видео вместе (слева плеер, справа чат);
- **Магазин**: на баллы пары покупаются вещи для комнаты и подарки партнёру;
- **Профиль**: два профиля (мой редактируется, партнёра только просмотр), настройки дома, приглашение партнёра, история баллов.

## Решения
| вопрос | решение | почему |
|---|---|---|
| бэкенд | Supabase напрямую из браузера (supabase-js с jsdelivr), RLS; на Vercel остаётся одна функция `api/config` | ключи лежат в env Vercel, Ваня их в чат не шлёт; лишний серверный слой не нужен |
| вход | почта + пароль, подтверждение почты выключено | бесплатный SMTP Supabase шлёт пару писем в час; Google-вход добавится одной кнопкой позже |
| пара | `couples` + `members` (в доме максимум 2, у человека один дом); приглашение = код/ссылка `?invite=код` | просто и проверяется сервером (`join_couple`) |
| данные дома | одна таблица `items(couple_id, kind, id, data)`, тот же API `store.all/get/put/del` | приложения не переписываются; удаление = `data:null`, иначе Realtime не фильтрует его по RLS |
| чат | отдельная таблица `messages` | растёт без предела, в общий `state` не грузится |
| «живое» | закрытый канал Realtime `couple:<id>` (RLS на `realtime.messages`): присутствие, «печатает», плеер, реакции | чужие пары канал не слышат |
| фото | Storage, корзина `house`, путь `<couple_id>/<uuid>.jpg`, публичные неугадываемые адреса | как было на Blob; закрытость через signed URLs можно сделать позже |
| баллы | общая копилка пары, лента `ledger` (+начисления, −покупки); суммы и цены только на сервере (`award`, `buy`) | из консоли нельзя начислить 10 000 или купить в минус; одно действие начисляется один раз (`unique(couple, reason, ref)`) + дневные пределы |
| локальный режим | без Supabase всё работает в localStorage, вкладки одного браузера синхронизируются через BroadcastChannel; `?as=b` открывает вторую половину пары | разработка и проверка без облака: две вкладки = Ваня и Соня |
| data.js | имена, дата и фото уходят в настройки пары/профили; в data.js остаются стартовые записки, альбомы и планы для нового дома | любой паре свой текст |
| перенос | при первом входе в облачный дом, если в браузере остались локальные данные, предлагается перенести их; data:-картинки догружаются в Storage | у Вани с Соней уже есть записки и фото |

## Модель данных (см. `supabase/schema.sql`)
- `profiles(id=auth.uid, name, emoji, color, avatar, birthday, about)` создаётся триггером при регистрации, виден себе и партнёру.
- `couples(id, title, started, invite)`, `members(couple_id, user_id unique)`.
- `items(couple_id, kind, id, data jsonb, updated_by, updated_at)`.
- `messages(id, couple_id, user_id, room, text, created_at)`.
- `ledger(id, couple_id, user_id, reason, ref, amount, item, to_user, note, opened)`; `shop(id, kind, price)`.
- RPC: `create_couple`, `join_couple`, `award(reason, ref)`, `buy(item, to, note)`, `open_gift(id)`, `server_now()`.

## Экономика
Начисления (сервер, `award`): ежедневный визит +5 (до 2 в день, по разу каждому), записка +5 (3/день), фото +2 (20/день), новый альбом +20 (3/день), этап плана +10 (10/день), план целиком +50, совместный просмотр 20 минут +30 (3/день).
Магазин: вещи для дома 40–220 (кактус, свечи, рамка, глобус, гирлянда-штора, торшер, пуф, ёлочка), подарки 20–150 (шарик, шоколад, букет, мишка, кольцо-шкатулка). Вещь для дома покупается один раз и встаёт на своё место в комнате. Подарок — коробка с бантом у партнёра в комнате с запиской; открыл, и подарок остаётся стоять в комнате.

## CoupleTube MVP
- Источники: YouTube (IFrame API) и прямые ссылки mp4/webm/HLS (hls.js). Vimeo, Twitch и Rutube подключаются потом через тот же интерфейс плеера (`load/play/pause/seek/time/rate/on`).
- Общее состояние `{src, type, playing, pos, at, by}` хранится в `items('tube','now')` и для скорости дублируется в live-канал. Ожидаемая позиция = `pos + (serverNow − at)`; при расхождении больше 1 с делается seek, при меньшем у html5 плеер мягко подгоняется скоростью 0.95–1.05. Смещение часов берётся из `server_now()`.
- Эхо собственных событий отсекается сравнением: событие плеера, совпавшее с общим состоянием, не публикуется.
- Чат справа: последние 100 сообщений, новые через Realtime, «печатает…», кто в сети и кто сейчас смотрит.
- Реакции ❤️😂😮😢🔥👏 вылетают поверх видео у обоих.
- Если 20 минут смотрели вдвоём (оба в CoupleTube, видео играет), паре начисляется +30.

## Ошибки
- Нет `api/config` или Supabase недоступен → локальный режим (как сейчас), сайт работает.
- Ошибка записи → `console.warn` и тост «не сохранилось»; кэш у себя остаётся.
- RPC с отказом (мало баллов, дом заполнен, неверный код) → понятный текст в интерфейсе.

## Проверка
- `node tests/sync.test.mjs`: математика синхронизации и определение источника по ссылке.
- Браузер, локальный режим: две вкладки (`?as=b`): записка/фото/план у одной появляется у другой, CoupleTube синхронизирует play/pause/seek, чат, «печатает», реакции, покупка, подарок и его открытие.
- Облако (после ключей): `api/config` отдаёт 200, анонимный запрос к `items` возвращает пусто (RLS). Вход и регистрацию проверяет Ваня: создавать аккаунты на внешнем сервисе мне нельзя.
